# 组内接入与维护约定

更新：2026-09-27。本项目采用 `src/`、`scripts/`、`tests/` 和 `examples/` 的普通开发布局。组内复用可以通过源码或 Python 包接入；本地运行无需安装 Skill。

## 代码、工具与数据

1. **项目代码**：核心位于 `src/htam_catalog/`，本地入口位于 `scripts/`，格式与行为通过测试维护。搬迁源码时保留该相对目录结构；演示另需 `examples/catalog/`。
2. **外部工具**：天工已有 CLI/Skills 按任务复用，分别确认实际入口、版本和兼容性。依赖观察清单记录已有证据。
3. **数据工作区**：通过 `--workspace` 指定；保存卡片、修订、索引及运行记录，详细 LCA 数据通过外部引用按需读取。

代码版本与数据修订分别管理。数据格式升级需要明确迁移和恢复办法；多用户服务及完整模型数据包交换属于后续接入设计。现有本地文件锁用于避免同时修改，同步共享与服务端协作仍需独立验证。

## 当前验证与接入事项

18 项行为测试包含在其他源码位置、其他当前目录运行命令，以及独立工作区的读写。实际执行环境为 WSL Ubuntu、Python 3.12。Windows 原生运行、Python 包安装、组内目标环境部署和在线天工集成尚未验证。

接入时分别检查代码入口、数据路径、上游命令的请求和响应、实际返回版本、认证方式及资料许可。账号会话沿用上游 CLI 或平台机制；共享内容保留来源和必要的访问条件。公开代码仓库为 `fpddmw/htam-catalog`，发布范围为本项目代码、样例和开发文档；组内运行数据独立维护，许可证尚未指定。

上游维护检索、解析、数据格式、认证及已有计算能力。本项目维护工艺卡片、接口目录、递归关系与必要的固定操作，已有能力通过其实际契约复用。使用命令见[目录工具](catalog-cli.md)，依赖边界见[天工复用](tiangong-reuse.md)。
