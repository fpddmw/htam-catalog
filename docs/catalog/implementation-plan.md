# 工艺目录基础设施建设计划

更新：2026-09-27。当前目标是把天工 LCA 已有的大量过程数据**批量、可重复地转换成可检索的工艺信息**，供跨类型发现、查询和潜在连接匹配使用。详细清单继续以天工为权威来源。本项目维护同步状态、工艺化投影、证据与检索入口。用户已明确先建设这条数据流水线，再根据真实数据优化库形态和 AI 查询接口。

## 当前已有内容与缺口

已实现 JSON 工艺卡片格式 v1、修订读写、来源刷新、简单字段检索、派生索引、递归层级展开和单步接口条件检查，见[目录命令](catalog-cli.md)。另有[天工原生模型只读检查](tiangong-model-inspection.md)，可读取本地构造模型的实例与连接。批量同步第一版及相关行为测试已加入，目前合计 27 项测试通过。

已有卡片仍需逐张准备，每次检索都会核对全部卡片。另已实现[天工批量同步第一版](tiangong-batch-sync.md)：使用 CLI 只读分页与本地 TIDAS 导出，建立 SQLite 工艺投影、增量更新与索引。真实账号的覆盖率、字段缺口、性能和长期分页一致性尚待测量；该投影目前独立于人工整理的卡片。

## 数据流水线

```text
天工过程、流、单位及来源（已授权 API 或批量导出）
  → 原始记录登记与同步状态
  → 确定性字段提取（过程身份、参考量、交换、流类型、单位等）
  → 工艺化解释（功能、接口语义、适用条件、证据与未知项）
  → 可查询索引、候选匹配与按需回查详细清单
```

**原始过程记录与工艺模块要分开。** 一条天工过程可能是黑箱、聚合结果、背景过程或具体工序；多条地区/年份不同的过程也可能对应同类技术。批量导入先保证每条源记录可追溯，再产生工艺摘要与候选关联；模块身份和整体/拆分关系通过实际字段与证据判断，不按过程名称自动合并。

确定性程序负责分页或分批读取、断点续跑、字段抽取、规范化、索引与变更检测。源记录能提供的字段直接保留其原义，例如产品流、废物流、基本流排放、参考交换、单位与数量基础。排向空气的 SO₂ 不能仅因名称相同就作为可供下游使用的产品接口。AI 可批量辅助判断功能、同义词、工艺边界、潜在接口和疑点；这些判断单独保存来源、生成方式与审阅状态，不覆盖原始字段。

每条导入记录至少要关联：来源系统、过程 ID、请求和实际返回版本、获取时间、内容散列、所属批次、提取状态与错误；工艺投影要保留流 ID、方向、交换类型、单位、参考量、来源字段位置及未知项。原件仍由天工维护；复现所需的选定快照及内容散列按数据访问和许可保存。本地不以复制整套 LCA 主库作为前置条件。

## 接下来按顺序完成

| 阶段 | 固定程序与数据交付 | 验收标准 |
| --- | --- | --- |
| A. 确认批量来源契约 | 已核实本机 CLI 0.1.22 的过程/流列表、分页与返回行结构；已用 TIDAS 样本适配 | 登录后核验真实组内权限、数据格式及过程/流/单位引用覆盖 |
| B. 批量摄取与增量同步 | 已实现分页、按来源身份和内容散列去重、断点恢复、失败表及逐批统计 | 离线测试已通过；须以真实数据验证完整性和长批次一致性 |
| C. 工艺化投影与质量报告 | 已提取过程身份、名称、行业、地区、年份、描述、交换及流类型；保留来源定位与散列 | 补齐真实数据缺失率报告、单位/流属性引用与黑箱/聚合标记 |
| D. 查询与匹配接口 | 已支持过程及流名称、行业、描述检索和同流 ID 的输出→输入线索 | 扩展结构化筛选、单位和条件检查，用真实规模测量覆盖率与性能 |
| E. AI 使用入口 | 在稳定的查询/回查/匹配命令之上提供机器可读接口，再按宿主需要添加轻量 Skill 包装 | AI 能调用同一套程序查询与追溯；核心转换和索引代码仍在本项目 `src/` |

存储形态随批量规模调整。现行 JSON 卡片可保留用于少量经整理的模块定义；同步台账、源记录与交换关系及检索索引需要支持批量写入和按流/类别查询。优先用实际数据测量当前全表核对的代价，再确定 SQLite/全文索引或组内已有服务的具体承载范围，不先发明第二套 LCA 主数据系统。

## 后续能力的位置

当前卡片的递归表达、实例与参数设计、拆分/替换、路径扩展、模型导出和 LCA 比较仍是已有技术方向，见[模型约定](model-contract.md)。它们依赖可用的工艺目录和源数据映射。先通过 A–E 得到可查询、可追溯的过程覆盖，再选择代表性记录检验这些操作需要哪些数据和补充模型。天工原生模型检查入口保留作为后续适配工具，不作为当前批量导入的完成证据。

持续向天工数据库补充数据是并行工作线，优先使用组内现成工具。本项目的数据流水线消费该库中的新增和更新记录，并把字段缺口与异常反馈给数据建设工作。真实工艺个案用于验证导入质量和检索效果，由批量结果选择，不以手工录入若干案例替代流水线验收。
