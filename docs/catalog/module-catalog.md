# 递归工艺模块库：工艺卡片与探索索引

更新：2026-09-27。定位与使用方式已由用户确认；卡片格式 v1、保存读取、字段检索、来源刷新、层级展开和标量接口条件检查已实现，见[本地命令](catalog-cli.md)。本页保留语义约定；定量模型目标另见[模型约定](model-contract.md)。

## 1. 库里保存什么

主体是可独立描述、引用和组合的工艺模块。模块以具体技术及其适用条件为单位，保存功能、接口、已知关系与证据。工艺卡片是模块的摘要记录；检索索引由卡片派生。

“工艺原子”表示当前资料和观察粒度下的可复用单元。一个模块在上一级流程中作为节点，自身可以继续包含子模块。叶节点表示当前尚未展开或尚无细节；整体清单和不同来源的拆分表达可以并存，分别保留边界、条件和依据。

区分类别、模块和实例：“干燥”可以是检索类别；特定技术及条件下的干燥是模块；某条路线中按本次规模和参数使用它，是实例。候选路线引用模块及所选表达，实例修改保存在该路线中。

## 2. 本地数据、天工和项目代码的分工

| 位置 | 职责 |
| --- | --- |
| 本地工艺目录 | 模块身份、功能及同义词、接口摘要、接收条件、整体/拆分关系、证据和外部数据映射 |
| 本地派生索引 | 按类别、功能、输入输出和条件检索；记录索引所依据的卡片内容，可重建 |
| 天工及其他来源 | 提供已有详细过程、流、单位、清单、模型与相应操作；实际能力按所用接口核验 |
| 工作区方案与运行资料 | 候选实例和连接、检查范围、未知项、修改和计算记录、必要缓存及复现快照 |
| 本项目代码与文档 | 维护和使用上述记录的方法、必要脚本、适配约定及小型可分发样例 |

本地目录具有独立的探索用途：上游已有的功能、接口或条件，也可以提取为有来源的摘要以便检索。详细记录按候选需要读取，完整 LCA 库同步不作为前置条件。模块可以先来源于文献或专利，清单与天工映射随后补充。

## 3. 工艺卡片的最小内容

以下是语义约定，字段及布局已在格式 v1 中落实。未知内容显式保留；卡片可在没有完整数量和 LCA 映射时进入目录。v1采用提取/本地两层及顶层字段来源追溯，更细的断言来源可在后续细化。

| 内容组 | 要记录什么 | 用途 |
| --- | --- | --- |
| 身份与组织 | 本地模块 ID、修订、技术名称、类别、同义词、行业或用途标签 | 跨来源检索与长期引用；名称相近时仍保留身份判断 |
| 功能与范围 | 完成何种转化或处理、技术边界、适用对象及条件 | 找到不同领域中承担相近功能的工艺 |
| 输入输出接口 | 局部接口 ID、方向、物料/能量/服务/环境交换类别、已知外部流身份 | 查找接收方、供给方或中间处理环节 |
| 接口性质与要求 | 组成、状态、必要物性；输入接收要求、输出已知性质或能力范围；数值的单位与基准 | 区分已知供给性质、接收要求及未知项 |
| 数量与参数入口 | 已有参考量、可调整参数、关系式或详细模型引用，及其来源、范围和缺口 | 支持后续定量化；有公式和可执行求值分别记录 |
| 内部表达 | 整体表示、可选拆分、子实例引用、连接与外部接口映射 | 按需要进入下一层，保留不同表达的差异 |
| 来源与外部映射 | 数据库记录、文献/专利身份与位置、映射关系和适用范围、版本/时间/必要散列 | 追溯依据和按需读取详细内容 |
| 可用程度与维护 | 接口与数量缺口、已检查条件、执行验证状态、更新时间与待刷新事项 | 返回可继续研究的候选和具体待补项 |

单一来源可作为整张卡片的默认依据；跨来源补充、数值推导、研究假设与修改另行定位。字段区分上游提取、有来源补充和研究推断。未知值与零值分别表达，已知不满足的条件保留。

## 4. 模块与外部记录的对应

模块与 LCA 记录允许多对多关联：一个技术模块可关联不同地域、规模或条件下的记录；一份聚合过程也可能为多个模块提供线索。每条关联注明完整对应、部分覆盖、聚合包含或候选对应，以及实际支持的字段和适用条件。

一个聚合数据集被多个模块引用时，分别记录其支持范围。子工序清单的分配和汇总依据另行核实。同名、同一流 ID 或同一来源都是匹配线索，模块同一性还需核对技术、边界和条件。

上游引用保存请求身份和实际返回身份。天工草稿可在同版本下修改，所查 CLI 存在版本回退逻辑；按复现需要记录获取时间、内容散列及选用快照。刷新时更新来源提取层，保留本地补充与假设；冲突和受影响卡片进入待核记录，派生索引随之重建。

## 5. 怎样用它探索路径

1. 从已知资源性质、目标功能或接收要求出发，先按工艺类别与功能找候选，再按接口和已知条件收窄。
2. 候选连接保存两端模块/接口、连接理由、已检查条件及其满足/不满足/未知状态。需要调质、运输或其他适配操作时，将相应模块纳入候选。
3. 搜索默认使用当前层模块的外部接口；寻找内部副产物流、替换点或细化条件时，再展开相应表达。当前包含关系须能够有限展开，物料回流另行表达。
4. 对值得继续检查的候选，按需读取详细过程及证据，补充数量和适用性判断；满足相应条件后接入定量计算和环境评价。

搜索按接口逐步扩展，记录实际覆盖的模块、条件及停止范围。接口匹配形成候选路径，工艺可行性判断对应已掌握的工程关系和证据。缺少条件的候选可以保留并返回明确问题；计算就绪程度独立记录。

## 6. 首版存储与使用验收

当前实现采用工作区内带修订及散列的 JSON 卡片和可重建 JSON 索引。原始层与本地层分别维护，刷新保留本地内容并形成新修订。独立方案持久化尚未实现；模块可以通过复合表达保存子实例与连接。SQLite、全文或语义索引按数据规模和真实检索结果再选择。

已有样例为8张构造卡片和1张已取得公开过程身份/名称摘要，覆盖整体/复合、三级层级及不同接口条件状态。文献工艺的真实参数与跨行业资料覆盖仍需继续积累，构造样例只用于软件验证。

验收应看到：卡片保存后可重开；按功能或接口找到预期候选并说明理由；未知条件仍可见；模块能关联多个来源；展开层级可追溯；来源刷新保留本地补充；索引可从卡片重建。具体脚本完成后以运行结果记录支持范围。
